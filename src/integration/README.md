# Cross-language binary acceptance harness

`main.mbt` uses only the public `starAndHonor/fst` API. A small tracked
`fixtures_generated.mbt` placeholder contains one empty-set case, allowing a
fresh checkout to compile and run without generation. Python temporarily
replaces it with the complete committed fixtures and expected records, so the
same harness runs without filesystem/FFI adapters on native, JavaScript and
Wasm-GC. A `finally` block restores the placeholder even after test failures.
The generated embedding is never included in the production code count.

```sh
python3 scripts/interop.py --target native
python3 scripts/interop.py --target js --target wasm-gc
python3 scripts/interop.py --case map_ascii --case map_u64_boundaries
python3 scripts/random_interop.py --target native --target js --target wasm-gc
```

The runner checks the complete decoded records, full unsigned 64-bit values,
declared record counts, lookups, a bounded range and arbitrary-byte prefix
queries. It also checks a MoonBit read/write round trip, then sends the
MoonBit-generated bytes to the pinned Rust process for checksum verification
and independent enumeration/query comparison. No C or Rust library is linked
to MoonBit.

The harness emits one `MOONFST_INTEROP` JSON line per fixture. A failed fixture
is reported independently so a codec failure is identifiable; the Python
acceptance command exits unsuccessfully if any case or comparison fails.
Compilation runs with `--deny-warn`.

Equivalent compressed graphs need not have identical bytes. The fixture
regeneration command, which uses the same upstream builder, separately requires
byte-identical Rust output.

The random differential command adds 64 cases and 6,508 records by default,
using SplitMix64 seed `0x4653544449464631`. It alternates sets and maps and
combines raw-byte keys, shared prefixes/suffixes, dense byte branching, nested
final-prefix chains and long common prefixes with zero, maximum, repeating,
decreasing and random unsigned outputs. `--seed` and `--cases` are explicit;
case names include the seed and ordinal so a failure can be regenerated.
These records are generated in memory and are not committed as extra fixtures.
Run these acceptance commands sequentially because they share the temporary
embedding. `--generate-only` writes an inspectable ignored
`fixtures_embedded.mbt.txt` file without changing compiled package sources.
