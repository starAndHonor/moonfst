# 查询优化与验收

2026-11-06，最终生产源码在完整验证后直接查询压缩字节。正式基准中，
两种分布、1,000 / 10,000 / 100,000 条的命中与近似未命中查询全部快于
Rust `fst 0.4.7`，六组最终编码文件长度均相同。

## 100,000 条结果

以下为每项 3 个独立进程、每进程 7 次采样的合并中位数。
每个 lookup 批次查询 100,000 个 key，时间单位 ms；加速比为 Rust / MoonBit。

| 分布 | 查询 | MoonBit | Rust | 加速比 |
|---|---|---:|---:|---:|
| 共享前缀 | 命中 | 6.798 | 13.036 | 1.92× |
| 共享前缀 | 未命中 | 6.155 | 12.825 | 2.08× |
| 随机字节 | 命中 | 6.917 | 10.713 | 1.55× |
| 随机字节 | 未命中 | 6.434 | 10.290 | 1.60× |

共享前缀文件两侧均为 **214,002 B**；随机字节文件两侧均为
**3,835,088 B**。这里比较编码文件尺寸；未测峰值 RSS。
基础 FST 只保留已验证的不可变字节和元数据，未添加完整图索引或 key/答案缓存。

其他操作完整保留在[正式报告](REPORT.md)：100,000 条的全量 owned 遍历基本持平；
前缀批次中位数仍慢约 2%～4%，并集慢约 15%～20%。随机数据构建快约
1.15 倍，共享前缀构建仍慢约 11%。这些数据不支持“全部操作都比 Rust 快”。

## 实现变化

1. `packed.mbt` 在完整验证后只读取查询选中的边，复用格式内的 256 字节索引。
   小节点用 UInt64 同时比较 8 个标签；旧 v1 大节点仍二分查找。
   一元节点使用标量局部变量，移除生成 C 中原先隐藏的元组分配。
2. `traversal.mbt` / `stream.mbt` 用压缩节点游标和值类型栈帧遍历，
   非终态单分支链保留在局部变量中；范围边界逐字节维护比较状态。
   批量消费不再构造每条结果的 Option；count/skip 不复制丢弃的 key。
   所有返回给调用方的 key 仍是独立副本，通用自动机的 EOF 语义保持不变。
3. `builder.mbt` 复用最大 key 深度范围内的可变节点对象，缓存改为与 Rust
   默认容量相同的 10,000 桶 × 2 槽。哈希相同后仍逐字段比较节点；
   只在缓存未命中时保存独立签名，可复用被淘汰签名的存储。
4. 编码器一次预留节点空间后写入；公共字符编码改为常量逆向查表。
   多路合并采用内联堆元素、替换堆顶和单次下沉，消除重复排序。

严格的公开解码与装载验证保留。私有按字读取依赖已验证字段范围和所有格式
至少 16 字节的 footer 余量；零宽度不读取，标签尾部的越界匹配会被拒绝。
完整图验证检查所有边的输出和与严格后退地址，覆盖死支路和非接受前缀。
安全前提及内存结构见 [ARCHITECTURE.md](../../../ARCHITECTURE.md)。

## 正确性证据

- `scripts/check.sh --min-production-lines=4000` 全部通过。
- Native / JavaScript / Wasm / Wasm-GC 各 **132 / 132** 项测试。
- Rust oracle 3 项、Rust benchmark 4 项、Python 协议和统计 16 项测试通过。
- 19 个固定样本及 64 个结构化随机样本，在 Native、JavaScript、Wasm-GC
  均完成双向解码和查询对拍；最终构建的 **83 个完整文件逐字节等于 Rust**，
  合计 22,431 条记录、756,663 B，详见 [builder-proof.json](builder-proof.json)。
- 新回归覆盖所有字节标签、压缩宽度 0..8、v1/v2/v3、256 路分支、长路径、
  范围组合、EOF 自动机、游标混合消费、返回 key 持有及 UTF-8 失败后继续消费。

生产 MoonBit 为 27 个文件、4,634 行非空非注释物理代码行；测试另计
4,707 行，基准和生成数据不计入生产代码量。

## 每 key 防优化屏障的控制实验

正式 Rust runner 在每次 get 的 key 上调用 `black_box`，MoonBit 未使用
相同的每 key 屏障。隔离对照只移除 Rust 的这两处 `black_box(key)`，
保留其他屏障、算法、依赖、数据与输出验证；三种程序轮换先后顺序，
均固定 CPU 2、3 轮 × 7 次采样。正式 runner 未修改。

| 分布 | 查询 | MoonBit ms | Rust 原 runner ms | Rust 去掉每 key 屏障 ms | 对控制组加速比 |
|---|---|---:|---:|---:|---:|
| 共享前缀 | 命中 | 6.652 | 12.506 | 12.773 | 1.92× |
| 共享前缀 | 未命中 | 6.101 | 12.303 | 12.337 | 2.02× |
| 随机字节 | 命中 | 6.866 | 10.613 | 12.081 | 1.76× |
| 随机字节 | 未命中 | 6.298 | 10.077 | 10.088 | 1.60× |

去掉该屏障后查询优势仍然存在。这是额外稳健性检查；各组代码生成及运行波动
仍有差异，不能把组间变化直接解释为屏障的固定开销。
[控制实验 JSON](lookup-barrier-control.json) 保留两行 diff、源码与程序哈希、
构建命令、参数、完整原始样本和校验结果。

## 复现与范围

```sh
bash scripts/check.sh --min-production-lines=4000
python3 scripts/benchmark.py --cpu 2 --output benchmarks/results/my-run
```

请选择本机可用 CPU 和新的输出目录。正式计时只串行运行一个被测进程；
系统频率、温度和其他用户程序未锁定。本轮是合成数据、排序查询、热运行、
native release 的库实现比较，不外推到所有语料、随机查询顺序、冷缓存或语言性能。
完整采样方法见 [benchmarks/README.md](../../README.md)，
原始结果见 [raw.json](raw.json) 与 [summary.json](summary.json)。
旧慢版本的数据和诊断保留在原目录；两次历史运行不是严格配对的因果实验。
